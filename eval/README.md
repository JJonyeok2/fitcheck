# 평가 준비

개발 시작 전에 해야 하는 것 두 가지.

## 1. 정답셋 (`labels.csv`)
- `labels_template.csv`를 복사해 `labels.csv`로 만든다.
- 실제로 본 공고 20개: 텍스트 공고 10개, 이미지 공고 10개.
  IT 직무가 아닌 공고 2~3개를 섞어 IT 직무 관문도 같이 확인한다.
- 공고를 직접 읽고 각 칸에 정답을 적는다. 모르는 칸은 비운다.
- `can_apply`: 내가 실제로 지원할 수 있는가 (Y/N). 자격 필터 정확도 측정에 쓴다.
- `my_judgement`: 내가 매긴 라벨. 라벨 기준(80%, 50%) 조정에 쓴다.
- 공고 원문과 이미지는 `eval/postings/<id>.txt|png`에 저장한다 (Git 제외).

## 2. 도입 전 시간 측정 (`time_log.csv`)
- 정답셋 중 10개로, 지금 방식대로 공고 읽기 → 지원 여부 판단 → 이력서 프로젝트 순서 정하기까지 걸린 시간을 기록한다 (`phase=before`).
- 완성 후 같은 공고 10개로 다시 잰다 (`phase=after`).

## 3. 모델 고르기
- 후보 2~3개로 이미지 공고 5개를 파싱해 핵심 필드 일치율, 공고당 비용, 응답 시간을 비교한다.
- 결과는 Spec 12장에 기록한다.
